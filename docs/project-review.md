# Проверка Service Desk — 6 ноября 2026

Это результаты первого прохода. Последующий этап доставки и фоновой обработки описан в [channel-reliability.md](channel-reliability.md).

Проверены исходники, запуск из Docker, существующие тесты, основные сценарии сотрудника и клиентский портал. Исправления внесены в проект. Проверка выполнялась в отдельном Compose-проекте `sd-audit` с собственной базой и тестовыми данными.

## Исправленные проблемы

| Область | Проблема | Результат |
|---|---|---|
| Права | Общие и клиентские отчёты были доступны инженеру, позволяя обходить ограниченную видимость заявок | Чтение, экспорт и создание отчётов ограничены руководителем и администратором согласно разделу 6 ТЗ; интерфейс учитывает эти права |
| Пагинация | При разных доменах/портах панели и API браузер не видел `X-Total-Count` | Заголовок доступен через CORS, полный размер очереди можно прочитать из браузера |
| Обзор | «Последние открытые заявки» включали закрытые; ссылка на просроченные не применяла фильтр | Открытые выбираются сервером до пагинации; переход из счётчика открывает соответствующую очередь |
| SLA | Просроченными считались в том числе приостановленные или уже выполненные таймеры решения | Счётчик и фильтр используют одинаковые условия; название «Просрочено решение» точно описывает показатель |
| Канбан | Закрытые заявки занимали места в ограниченной серверной выдаче, а затем скрывались на клиенте | Закрытые и отменённые исключаются до пагинации; решённые остаются на доске до закрытия; ошибка перемещения видна пользователю |
| Фильтры | Очередь частично игнорировала параметры ссылки; сохранённые фильтры не учитывали область очереди | Параметры ссылки восстанавливаются, проверяются и обновляются; есть сброс и сохранение области; переключение вида сбрасывает страницу |
| Даты | Преобразование локальной даты в UTC сдвигало первый день отчётного месяца и даты списаний | Даты форм, отчётов и договоров формируются в локальном календаре |
| Часовые пояса | «Сегодня» и дни недельного графика определялись по UTC | Обзор учитывает часовой пояс браузера, включая группировку заявок по дням |
| Сессии | После истечения токенов интерфейс оставался открытым; кэш сохранялся между пользователями | Завершение сессии очищает состояние и кэш; после входа восстанавливается запрошенная страница; поздний refresh не восстанавливает завершённую сессию |
| Портал | Истёкшая сессия не возвращала на вход; эффект повторно расходовал magic-link в режиме StrictMode | Сессия обрабатывается единообразно, magic-link расходуется один раз |
| Связи данных | Можно было привязать актив другой организации; форма сохраняла актив после смены клиента | Форма очищает актив, сервер проверяет организацию; при переносе заявки неподходящая связь снимается с записью в историю |
| Изменение заявки | Неверные ссылки на категорию, команду или исполнителя могли доходить до БД и уведомлений | Ссылки проверяются до изменения статуса и отправки уведомлений; неактивного исполнителя назначить нельзя |
| Контакты | Повторный email/телефон приводил к ошибке 500 | Адреса нормализуются, повторы внутри формы убираются, конфликт возвращает понятную ошибку 409 |
| Вложения | Сбой загрузки файла после сохранения сообщения приводил к повторной отправке текста при повторе | Незагруженные файлы повторно прикрепляются к уже созданному сообщению; ошибки скачивания видны; в портале можно отправить файл без собственного текста |
| Отчёты | Обратный/пустой период, необработанная ошибка экспорта и отображение `—%` | Добавлены проверка периода, состояние выгрузки и понятная ошибка; отсутствие данных отображается как `—` |
| Интерфейс по ролям | Инженеру предлагались действия справочников, запрещённые сервером; пустая загрузка команды выглядела как отсутствие назначений | Недоступные действия скрыты/отключены, управленческий виджет нагрузки скрыт для инженера |
| Запуск | Адрес API по умолчанию указывал на localhost браузера, что мешало работе с другой машины | По умолчанию используется `/api` на домене панели; добавлен такой же прокси в Vite и зависимость frontend от API-прокси |
| Проверки | `npm run lint` вызывал отсутствующий ESLint | Настроены ESLint, TypeScript и React Hooks; устранены замечания; lint и тесты frontend включены в CI |
| Зависимости | Аудит находил уязвимые версии frontend и Python-библиотек | Обновлены зависимости и lock-файл; сборка frontend и CI используют Node.js 22 |

В `package.json` закреплён безопасный `minimatch` через `overrides`: текущие версии ESLint и TypeScript ESLint ещё запрашивают уязвимую ветку. Совместимость проверена запуском линтера и сборки.

## Оформление

Единые отступы, типографика, карточки показателей, поля, таблицы, кнопки и уведомления. Обновлены экран входа, боковая навигация и обзор работы. Добавлены переключение светлой/тёмной/системной темы, мобильное меню, перенос форм в одну колонку, локальная прокрутка широких таблиц, видимый клавиатурный фокус, ссылка перехода к содержимому и учёт reduced motion. Подписи основных форм связаны с полями, приоритеты локализованы.

## Проверки

- Полный набор backend: **485 тестов прошли**, `python -m pytest tests/ -q` внутри контейнера.
- Frontend: **6 тестов прошли**; `npm run lint`, `npm test`, `npm run build` завершаются успешно.
- Аудит зависимостей: `npm audit` и `pip-audit -r requirements.txt` не находят известных уязвимостей на дату проверки.
- Браузер: 24 раздела при ширине 1440 px; обзор, очередь, создание заявки, отчёты и карточка при ширине 390 px; светлая и тёмная темы. Ошибок JavaScript, ответов 500 и горизонтального переполнения страницы в этом проходе нет.
- Сквозные сценарии: создание заявки, смена организации с выбранным активом, переход из показателя просрочки, мобильная навигация, вход инженером и запрет отчётов, сбой загрузки вложения с повтором без дублирования сообщения, вход в портал, отправка файла и возврат на вход при истечении сессии.

Новые регрессионные тесты находятся в `backend/tests/test_project_review.py` и `frontend/tests/regressions.test.mjs`.

## Границы проверки

Проверка подтверждает перечисленные сценарии и исправления. Боевые SMTP/IMAP, MAX, Telegram, Plusofon и Zabbix в это окружение не подключались: их реальные входящие/исходящие события требуют проверки на соответствующих учётных данных. Для вложений проверены сохранение и доступ внутри Service Desk и портала; фактическая доставка файлов через внешние каналы не проверялась. Нагрузочный прогон на производственном объёме данных и промышленное развёртывание в эту проверку не входили.

## Обновление оформления и навигации

Заменена буквенная плашка «ОГ» на единый векторный знак `frontend/public/brand-mark.svg`. Добавлены фавиконы SVG, PNG 32×32, ICO и Apple Touch Icon 180×180. Обновлены светлая и тёмная палитры, боковая навигация, карточки показателей, таблицы, фильтры, формы, проекты и клиентский кабинет. Визуальные уточнения собраны в `frontend/src/styles/workspace.css`.

В верхней панели появился быстрый поиск разделов, заявок и проектов с Ctrl/⌘K, стрелками и Enter; Escape закрывает окно с восстановлением фокуса. Поиск использует существующие API с ограничениями видимости. На входе добавлена кнопка показа пароля. Меню групп свёрнуто по умолчанию, текущий раздел раскрывается автоматически.

Проверки: 8 frontend-тестов, ESLint и производственная сборка прошли. В браузере проверены загрузка знака и четырёх форматов иконок, переключение видимости пароля, поиск и переходы с клавиатуры, закрытие по Escape, мобильное меню, светлая и тёмная темы. При ширинах 320, 390, 768, 1024 и 1440 px переполнения страницы и основного контейнера не обнаружено; ошибок JavaScript нет. Внешние сообщения не отправлялись.
